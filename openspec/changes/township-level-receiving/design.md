## Context

現有的地理流動分析（既有的地理建置腳本）用統計出版品的 `A1-5`（出生戶籍地）與
`A1-6b`／`A1-6a`（學校所在地）三張表，粒度都是縣市。承接端因此只能講到
「某縣市承接多少原民生」，講不到縣市內部的分布。

社會經濟資料服務平台（SEGIS）的《行政區大專校院統計》屬「教育文化／教育」類，
空間範圍全國，空間統計單元為縣市與鄉鎮市區。欄位同時含
「大專校院原住民學生數」「大專校院男原住民學生數」「大專校院女原住民學生數」
「大專校院學生數」「大專校院學校數」，因此原民生占比的分子與分母在同一列。

年度標示為**學年**（`INFO_TIME` 值形如 `114Y`，產品名稱寫「114學年」），
與教育部端 104–114 學年的流動資料同為學年度口徑，可置於同一條時間軸。

約束條件：

- 本資料的原始統計機關即教育部統計處，與既有的出版品同源，因此不是獨立來源。
- 平台的資料集清單查詢是加密的 POST 請求，無法純腳本列舉（見下方決策）。
- 專案既有的 SEGIS 抓取腳本走的是 data.gov.tw 的 dataset 詮釋資料路徑，
  該路徑不適用於本資料集（見下方決策）。

## Goals / Non-Goals

**Goals:**

- 承接端粒度從縣市降到鄉鎮市區，並在「縣市」報告頁呈現。
- 原民生占全體大專學生的比率，在鄉鎮市區層級可得，且分母來自同一列。
- 縣市加總與教育部統計出版品的關係被實測並寫入文件，包含不一致時的處置。
- 抓取結果可在本機重建，不需每次都連線。

**Non-Goals:**

- 不做科系或學門維度——本資料只有原住民學生總數。
- 不做族別維度——本資料沒有族別欄位。
- 不改動流出端（出生戶籍地）的粒度。
- 不改動原住民成年人口學歷結構（存量）的資料來源版本。
- 不把本資料當作教育部數字的獨立交叉驗證來源。
- 不新增高級中等學校資料。
- 不在執行期自動發現 oCode。
- 不做時間序列，不實作平台的登入下載流程。

## Decisions

### 以一次性取得的 oCode 常數存取行政區開放服務端點

取數走 `GetAdminSTDataForOpenCode`，其唯一參數 oCode 寫成抓取腳本裡的常數。

實測依據（本次驗證，不是推測）：平台清單查詢是 POST 到 `reqcontroller.go`，
method 參數必須是加密後的請求碼，明文送出回應 HTTP 401「認證失敗 : 請求碼不正確」；
另外嘗試 data.gov.tw 的前端搜尋路徑回應 HTTP 404，該路徑不存在。

替代方案與否決理由：讓腳本每次執行時自行搜尋資料集以取得 oCode——否決，
需要複製平台的請求碼加密邏輯，那是未公開且會隨前端改版失效的相依。
改走 data.gov.tw dataset 詮釋資料（既有 SEGIS 腳本的做法）——否決，實測該資料集
不在那條路徑上。

oCode 本身的取得方式（一次性，人工）：在平台查詢介面以名稱搜尋、點資料名稱開啟
資料檢視頁，該頁 HTML 原始碼含四個開放服務網址（JSON／XML／GeoJSON 兩種投影），
取其中的 JSON 版。取得後連同取得日期一起寫進腳本註解。

### 縣市加總的比對對象是 A1-6a 而非 A1-6b

本資料範圍是大專校院。平台上「宗教研修學院」與「空大及大專校院附設進修學校」
是各自獨立的資料集，因此本資料不含這兩類，與 `A1-6a` 的範圍一致，
而 `A1-6b` 含這兩類。

驗證順序：先比對 `A1-6a`；若不符再比對 `A1-6b`，並把實測到的差額量級記錄下來。
既有文件已載明 `A1-6a` 與 `A1-6b` 的總計差約 1,700 人，可作為判讀依據。

替代方案：直接假設對得上 `A1-6b`——否決，範圍不同會讓比對在應該通過時失敗，
或在不該通過時因量級接近而被誤判為通過。

### 鄉鎮市區代碼直接採用資料自帶的行政區代碼

行政區系列的回應帶正式的縣市與鄉鎮市區代碼，不是發布區那種無法還原的內部序號。
因此鄉鎮層級可直接對接行政區圖資，不需要任何代碼還原推測。

這一點與既有存量腳本的處境相反：那支用的是統計區版，發布區代碼接不回鄉鎮市區，
所以只能做到縣市。本變更不動那支腳本。

### 欄位對照以名稱比對確認，不靠位置順序

回應的 `ColumnList` 帶 `COLUMN_NAME` 與中文 `COLUMN_DESC`，本次需要的欄位為
`INFO_TIME`、`COUNTY_ID`、`COUNTY`、`TOWN_ID`、`TOWN`、`SCH_CNT`、`STU_CNT`、
`NA_STU_CNT`、`NA_STU_M_CNT`、`NA_STU_F_CNT`。

腳本以**欄位名稱**取值，並在解析前檢查所需欄位是否全數存在於 `ColumnList`，
缺任一個即中止。不得以欄位在陣列中的位置取值。

這與語言普查那份的情況相反——那份的欄位是無語意的 `FLD01`–`FLD07`，且詮釋資料頁
兩處順序互相顛倒，只能用已知地區數值反推。本資料沒有那個問題，但仍須驗證欄位存在。

替代方案：信任欄位順序——否決。平台改版時新增欄位會讓位置取值靜默錯位，
那種錯不會報錯，只會產出一張錯的地圖。

### 範圍限於 114 學年一期，因為開放服務端點取不到歷年

實測依據：官方文件寫明 `oCode` ＝ 主題代碼＋統計單元代碼＋資料格式，**不含年度**；
`OpenService.asmx` 只有 GetAdmin／GetOrg／GetStat 三個方法，全部只吃 `oCode`，
沒有時間參數；平台上 99 至 114 共 16 個學年的產品頁，回傳的 `oCode` 完全相同，
而該 `oCode` 的資料 `INFO_TIME` 全為 `114Y`。

替代方案與否決理由：走平台「連結」按鈕給的檔案下載網址
（`reqcontroller.go?method=filedown.downloadproductfile`，method 是明文且帶
`STTIME` 年度參數）——**本變更否決**。未登入直接請求只會回傳平台首頁 HTML，
需要帳號登入；且取得的是 16 個下載檔而非 API，重建流程會變成半手動。
若日後要做時間序列，那是獨立變更，並須先解決登入。

輸出仍採長格式並保留 `年度` 欄，使日後補進歷年時不需改變資料形狀。

### 一次請求即涵蓋全國，不逐縣市取數

平台清單把本統計依縣市列成 21 筆「_鄉鎮市區_○○縣」產品，但實測任一縣市入口的
`oCode` 回傳的都是**全國 87 個鄉鎮市區、21 個縣市**的完整資料。因此只需一次請求。

這與既有存量腳本的處境不同：那支因平台無彙總檔而必須逐縣市抓取 22 個檔。
不要沿用那個模式。

## Implementation Contract

**行為：** 執行抓取腳本後，本機出現行政區大專校院統計的原始回應快取；
執行建置腳本後，產出鄉鎮市區層級的承接端明細與縣市層級摘要兩份 CSV；
執行既有的報告輸出腳本後，「縣市」報告頁出現鄉鎮層級承接端區塊。

**資料形狀：**

- 明細輸出 `out/receiving_township.csv`，一列一個「學年 × 鄉鎮市區」（本變更只有
  114 學年一期，保留學年欄是為了日後補歷年時形狀不變），欄位為：
  學年、縣市代碼、縣市、鄉鎮市區代碼、鄉鎮市區、學校數、全體學生數、
  原住民學生數、原住民男學生數、原住民女學生數、原民生占比。
- 摘要輸出 `out/receiving_township_summary.csv`，一列一個縣市，為最新一期的
  縣市加總，欄位為：縣市代碼、縣市、鄉鎮數、學校數、全體學生數、
  原住民學生數、原民生占比。
- 原民生占比定義為原住民學生數除以全體學生數，全體學生數為零時輸出空值而非零。

**失敗模式：**

- 抓取失敗、回應非預期格式、或欄位對照數量不符：中止並列出實際收到的欄位，
  不寫出部分結果。
- 原住民男學生數與女學生數之和不等於原住民學生數：中止並指出學年與鄉鎮市區。
- 鄉鎮加總後的縣市數字與 `A1-6a` 對不上：不靜默通過。腳本印出逐縣市差額，
  並在文件裡記錄實測結論；差額若源自範圍差異則明確寫出是哪一類差異。
- 缺少快取且無法連線：中止並提示先執行抓取腳本，不改用線上即時取數。

**驗收條件：**

- 抓取腳本在無網路但有快取的情況下可重跑成功。
- 明細 CSV 的鄉鎮市區數為 87，橫跨 21 個縣市（遠小於全國 368 個鄉鎮市區）。
- 114 學年的全國原住民學生總數與統計出版品的同學年總計，差額可被範圍差異解釋。
- 男女分項加總等於總數，逐列成立。
- 報告頁的鄉鎮區塊在瀏覽器中可見，且其縣市加總與頁面既有的縣市層級數字並置時
  不互相矛盾——若矛盾，頁面須標明兩者範圍不同。
- 全體學生數低於 1,000 人的鄉鎮，其占比在頁面上標為不穩定。
- 文件中明確寫出本資料與教育部出版品同源，不宣稱為交叉驗證。

**範圍內：** 抓取、建置、鄉鎮層級呈現、與出版品的一致性比對及其文件化。

**範圍外：** 高級中等學校資料、存量資料來源的版本更換、流出端粒度、
科系與族別維度、114 學年以外的年度、平台登入下載流程、時間序列的視覺化。

## Risks / Trade-offs

- oCode 為寫死常數，平台若換發會失效 — 取得日期寫進註解；失效時的錯誤訊息
  明確指向重新取得 oCode 的步驟，而非讓腳本安靜產出空結果。
- 本資料與教育部出版品同源，讀者可能誤以為兩份數字相符構成互相驗證 —
  文件與頁面都明寫同源，並把價值定位在粒度與年度長度。
- 鄉鎮層級的原民生人數在多數鄉鎮偏小，比率易被小分母放大 — 呈現時對全體學生數
  低於 1,000 人的鄉鎮標註為占比不穩定，不讓極端比率主導視覺。門檻取 1,000 是因為
  單一小型校區規模即在此量級，低於此數時一名學生的增減就會顯著移動比率。
- 只有 114 學年一期，無法呈現趨勢，讀者可能誤以為鄉鎮的承接規模一向如此 —
  頁面明寫這是單一學年的快照，不是趨勢。
- oCode 回傳的永遠是平台當下的最新一期，明年會變成 115 學年而腳本不會察覺 —
  學年欄直接取自回應的 `INFO_TIME`，不寫死；文件與頁面的學年字樣一律由資料帶出，
  避免出現「標題寫 114、數字其實是 115」。

## Migration Plan

新增輸出檔，不改動既有輸出的欄位，因此既有頁面與 CSV 的消費者不受影響。
回退方式是移除報告頁新增的區塊與兩份新輸出，既有流程不需還原任何東西。

## Open Questions

原提案的三個問題已於 2026-08-11 實測解決，結論已寫入上方決策：oCode 已取得、
年度標示為學年（`114Y`）、一次請求即涵蓋全國 87 個鄉鎮市區。

尚未解決：

- 縣市加總與 `A1-6a` 的實際差額尚未量測，須待實作時比對。若差額無法由範圍差異
  解釋，須在文件中如實記錄而非調整資料。
- 歷年（99–113 學年）需登入平台下載，登入後取得的檔案格式與欄位是否與開放服務
  一致，尚未確認。這屬於未來變更的前置問題，不影響本變更。
